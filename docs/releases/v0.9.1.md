# VisitorPortal v0.9.1

Security maintenance release for existing VisitorPortal installations.

## Security Updates

- PHP runtime updated to **8.4.27**, including fixes for [CVE-2026-109618](https://github.com/php/php-src/security/advisories/GHSA-w8hw-w9fx-j79w) and [CVE-2026-109619](https://github.com/php/php-src/security/advisories/GHSA-6wmf-4rv5-p3rp).
- PHP dependency updates addressing the 52 Composer advisories reported against v0.9.0, including Laravel 12.70.1, Filament 5.10.3, Livewire 4.4.8, Guzzle 7.16.0, CommonMark 2.10.4, WebAuthn 5.3.9 and JWT Library 3.4.10.
- Frontend/build dependency updates addressing 13 additional npm audit findings.
- Refreshed Filament JavaScript, CSS and fonts. Composer's post-autoload hook synchronizes the published assets; the production Docker build includes those generated assets.

## Release Packaging

- Explicit production Docker build target `app` and updated PHP base image.
- Demo and source ZIPs built together with the versioned image; GitHub release draft using these versioned notes.
- Release-tag check against `main`; `latest` image updates limited to stable version tags.
- Demo reset script starts `start.sh` through `sh`, including when executable permission is absent.

## Upgrade From v0.9.0

- **No application database migration changes** and no changes to application role/permission definitions in this release. An already fully migrated v0.9.0 database is expected to have no pending migrations from this update.
- Retain the existing database, storage volumes, configuration and **`APP_KEY`**. The key is required to decrypt existing encrypted application data, including MFA secrets.
- Back up the database, storage and configuration, and verify the update on an isolated copy of the existing installation before production rollout.
- Docker deployments: update **app, queue and scheduler** to the new image together. The image includes the patched PHP runtime and built dependencies/assets; PHP and Node.js are not required on the Docker host.
- Production Compose keeps `AUTO_MIGRATE=false`, `AUTO_SEED=false` and `FORCE_SEED=false`. Run the controlled migration check described in the update guide.
- Source/LAMP deployments: both CLI and Apache/PHP-FPM require **PHP `>=8.4.27,<8.5`**. PHP 8.5 is not accepted by the current `~8.4.27` Composer constraint. Install dependencies from the committed lockfiles with Composer scripts enabled and rebuild frontend assets using Node.js 24.
- No demo reset, database reseeding, new admin creation or application-key regeneration is required. Do not use `migrate:fresh` or `docker compose down -v` for this update.
- Existing demos: set the new version in the existing `.env.demo`, then run `sh update.sh` or `update.bat`. If `VISITORPORTAL_IMAGE` is set, update that reference instead. The update script does not automatically choose a newer release.

See the [production Docker and source/LAMP update procedure](https://github.com/P0etInc0de/VisitorPortal/blob/v0.9.1/docs/deployment.md#updates) for commands, preservation requirements, health checks and rollback considerations. Demo update instructions are in [Setup](https://github.com/P0etInc0de/VisitorPortal/blob/v0.9.1/docs/setup.md#stop-reset-and-update).

## Container Image

```text
ghcr.io/p0etinc0de/besucherportal:v0.9.1
```

For the production `.env`:

```env
VISITORPORTAL_IMAGE=ghcr.io/p0etinc0de/besucherportal:v0.9.1
```

For an existing demo's `.env.demo`:

```env
VISITORPORTAL_VERSION=v0.9.1
```
